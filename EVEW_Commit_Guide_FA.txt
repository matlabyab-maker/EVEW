راهنمای ساخت مخزن تازه EVEW با GitHub و MGit

این بسته، پروژه ویرایش ویدیو را با نام مخزن و ریشه Gradle برابر EVEW آماده می‌کند.
شناسه مستقل اندروید EVEW: com.evew.app؛ این شناسه با پروژه EVC مشترک نیست.

۱) آماده‌سازی فایل‌ها
- فایل EVEW.zip را استخراج کنید.
- خود پوشه EVEW را در MGit به‌عنوان ریشه پروژه انتخاب کنید.
- فایل‌های settings.gradle.kts و build.gradle.kts و پوشه‌های app و .github باید مستقیماً داخل EVEW باشند.
- این بسته عمداً پوشه .git، تاریخچه Git و Remote قبلی را ندارد؛ مخزن محلی تازه بسازید.
- فایل‌ها و پوشه‌های مخفی را نمایش دهید و مطمئن شوید .github نیز همراه بقیه فایل‌ها انتخاب شده است.

۲) ساخت مخزن در GitHub
- یک Repository کاملاً خالی با نام دقیق EVEW بسازید.
- هنگام ساخت، README یا فایل اولیه را به‌صورت خودکار اضافه نکنید.
- آدرس HTTPS مخزن تازه EVEW را پس از ساخت در MGit به‌عنوان Remote اضافه کنید.

۳) اولین Commit و Push در MGit
- پوشه EVEW را به‌عنوان مخزن محلی باز/ایجاد کنید؛ پوشه والد یا پوشه تودرتوی دیگری را انتخاب نکنید.
- همه فایل‌ها، از جمله فایل‌ها و پوشه‌های مخفی مانند .github، را Stage کنید.
- اولین Commit را با پیام Initial EVEW project ثبت کنید.
- شاخه محلی را به مخزن GitHub تازه Push کنید.

۴) بررسی GitHub Actions
- پس از Push، زبانه Actions را باز کنید.
- Workflow با نام EVEW Android Build باید اجرا شود.
- مسیر فایل آن دقیقاً .github/workflows/android.yml است.
- تریگر Push و Pull Request برای همه شاخه‌ها فعال است و اجرا فقط به main یا master محدود نیست.
- اجرای دستی نیز با workflow_dispatch فعال است.
- نام ثابت Artifact در فایل Workflow هنوز EVEW-0.2.191-ARM32-debug-apk است؛ فایل YAML عمداً تغییر داده نشده است. نسخه داخلی برنامه 0.2.193 است.

۵) اگر Commit یا Actions ظاهر نشد
- در MGit بررسی کنید Commit واقعاً ثبت شده باشد و فایل‌ها در حالت Stage/Commit باقی نمانده باشند.
- بررسی کنید Remote به مخزن تازه EVEW اشاره کند، نه مخزن قدیمی VEFt.
- در GitHub شاخه‌ای را که Push کرده‌اید باز کنید و وجود فایل .github/workflows/android.yml را بررسی کنید.
- اگر فایل workflow در GitHub نیست، فایل‌های مخفی را در MGit نمایش دهید، .github را Stage کنید و Commit/Push را تکرار کنید.
- در GitHub بخش Actions و فعال بودن Workflow را بررسی کنید.
- اگر Workflow اجرا شد ولی Build شکست خورد، متن کامل خطای همان اجرا را ارسال کنید.

نکته مهم:
فایل workflow موجود در این بسته از قبل branches: ["**"] دارد؛ بنابراین شاخه‌های غیر از main و master نیز پوشش داده می‌شوند. نام برنامه و شناسه اندروید تغییر نکرده‌اند؛ فقط نام پروژه/مخزن EVEW شده است.
